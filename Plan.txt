Goal Description
The hospital-admin-service is returning a 403 User not authenticated error for PATIENT users through the api-gateway on endpoints like /api/v1/hospital/health-services and /api/v1/hospital/doctors.

This occurs because:

JwtAuthGuard
 in dev mode (SKIP_APPOINTMENT_AUTH) explicitly skips JWKS validation and returns true for /hospital routes without decoding the payload, leading to an undefined req.user.
Even with req.user decoded, 
HospitalAdminController
 indiscriminately applies @Roles(UserRole.HOSPITAL_ADMIN, UserRole.SUPER_ADMIN) to ALL methods, preventing PATIENT or DOCTOR from accessing read-only endpoints like doctors lists and health services.
Proposed Changes
1. Fix Missing User Decoding in JWT Auth Guard
We will update 
JwtAuthGuard
 to decode the JWT payload for /hospital routes when checking skipAuthForDev, ensuring req.user is properly attached.

[MODIFY] 
jwt-auth.guard.ts
In the skipAuthForDev block, extract and decode the token for /hospital routes so req.user is populated before returning true. This will prevent the 
RolesGuard
 from throwing a 403 User not authenticated error.
2. Relax Access Controls for GET Requests in HospitalAdminController
We will split the catch-all proxy routes in 
HospitalAdminController
 by HTTP method to allow PATIENT and DOCTOR users to make GET requests, while restricting mutations (POST, PUT, PATCH, DELETE) to HOSPITAL_ADMIN and SUPER_ADMIN.

[MODIFY] 
hospital-admin.controller.ts
Remove the class-level @Roles(UserRole.HOSPITAL_ADMIN, UserRole.SUPER_ADMIN) decorator.
Replace @All('*') proxyRequest(...) with multiple explicitly mapped endpoints (@Get('*'), @Post('*'), @Put('*'), @Patch('*'), @Delete('*')).
Apply @Roles(UserRole.PATIENT, UserRole.DOCTOR, UserRole.HOSPITAL_ADMIN, UserRole.SUPER_ADMIN) to the GET methods.
Apply @Roles(UserRole.HOSPITAL_ADMIN, UserRole.SUPER_ADMIN) to the POST, PUT, PATCH, and DELETE methods.
Do the same for the base / path handler.
Verification Plan
Manual Verification
Start the API Gateway and verify that it compiles and boots without errors.
Ensure you can access http://localhost:8080/api/v1/hospital/health-services and http://localhost:8080/api/v1/hospital/doctors with a valid PATIENT or DOCTOR Bearer token.
Verify that accessing a POST endpoint (e.g. POST /api/v1/hospital/doctors) with a PATIENT token properly returns a 403 Insufficient permissions error instead of succeeding.
